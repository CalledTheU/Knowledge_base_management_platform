# Knowledge Base Management Platform - Handoff

## Current stage: FAQ automation, dashboard trends, and chat history (2026-09-28)

- Completed: FAQ mining now runs every five minutes and can be triggered on demand. Similar questions are clustered from chat logs at a default frequency threshold of two; reruns recalculate counts idempotently. Candidate cards include an average similarity score and linked global knowledge. Private or role-scoped source chats are excluded because the FAQ cache is shared.
- Completed: dashboard reports PV/UV, FAQ hit count/rate, daily question and token trends for 14 days, response-time buckets, and existing top question/knowledge rankings. Charts use existing CSS and require no chart dependency.
- Completed: chat sessions and messages persist by user, history restores with citation titles, and up to six prior authorized turns feed retrieval and answer generation. History is rechecked against current document ACL/enabled status before display or reuse; the UI lists the latest 30 sessions and exposes them on mobile.
- Verification: `.venv\Scripts\python.exe -m unittest discover -s tests -v` -> 17 passed, including FAQ idempotency/private-source filtering, session ownership and ACL revocation, context passed to the LLM, dashboard aggregates, and legacy DB migrations. `node --check front/app.js`, Python compilation, and `git diff --check` passed. Playwright verified login, FAQ refresh, multi-turn restore, charts with data, and 390px mobile layout without horizontal overflow.
- Limitations: FAQ similarity/confidence is a lexical heuristic, not a calibrated semantic model; the five-minute worker runs inside the web process, not a durable job queue. Charts are compact native bars, not ECharts. Previously published/manual FAQ answers still rely on curator review.
- Not completed in the full requirements: JWT authentication, folder-recursive import, native model-token streaming with Markdown/code rendering, and broader real-PDF external RAG acceptance remain.
- Next: continue full-requirement acceptance, starting with a real PDF import/query on the configured MinIO/Milvus/DeepSeek services, then address the remaining authentication and chat presentation requirements.
